Do the same for each later `nextAction.tool`; that field is a logical name, never a callable `mcp__plugin_bypass_security.*` ID. Search again if a tool is unavailable or the session is compacted. This command contains the setup instructions, so load the full bypass skill only when beginning assessment. Pass repository, URL, environment and review type already supplied in the conversation. For Code + running app or Running app only, set `reviewScope: true` once when the app is connected, including when testing permission was saved earlier, so the user can keep or change its methods, paths and rate. After the permission choice, continue to assessment without reopening that picker. Use the next action embedded in each tool result instead of rereading onboarding after every step.

1. If the review type is unknown, open its native picker: Code only, Code + running app, Running app only. Retain custom instructions. Suggest the current folder only if the tool confirms it contains application source. A home directory is not an application. Connect a supplied Git URL before proceeding with code setup; app-only needs no repository.
2. Ask only for a missing URL/path. Use the native environment picker only if the environment is unknown. Retain supplied answers. Continue automatic setup actions without asking whether to continue.
3. In Code + running app, follow the wizard's method, RPS, Muse-call and time-budget questions in order. Send each answer back to `bypass_onboarding`; a suggested default is an answer only when the user selects it. The five-minute choice is a quick, partial-coverage test. The time budget starts when source review begins and applies to the connected full live audit; the plugin cannot interrupt Muse Code reasoning mid-step. Then show the compact proposed test scope: app, environment, paths, methods and rate. Ask **Do you control this app and authorize these tests?** with **Approve**, **Decline**, **Custom instructions**. Use the returned picker. Approve explicitly confirms control and the displayed scope; a preselection or custom note is not approval. Explain write-method effects briefly. Custom instructions can change paths and methods. If the plan changes, show it again before approval. Decline saves setup and runs nothing.
4. Domain verification is configured with project setting `ownershipVerification`: off, dns, or http. New projects use off; existing projects keep their setting. Show DNS TXT or HTTPS-file steps only when required. Never call an operator acknowledgment verified ownership. On request, use `bypass_config` and `bypass_set_config`; do not ask the user to edit JSON. Changing this setting clears testing permission.
5. After approval, authorize the exact displayed scope, including production only if shown and approved, then continue the requested review. If the user asked only for setup, finish with setup saved. Load the bypass skill before assessment. Accounts are optional; reuse saved accounts and discover missing configuration. Account creation needs its own explicit permission unless already granted. Do not edit application code to fix findings without a separate request.

Use any Muse-call and minute limits already supplied; otherwise use the defaults of 120 and 30. A requested five-minute test uses `minutes: 5` and explicitly reports partial coverage. A blackbox start without `review` or `finding` remains an independent full audit; `finding` requests a separate focused check.

The test approval did not authorize editing application code; selecting the fix choice is a separate remediation request. If the user already requested remediation, proceed without asking again. On approval, continue the same workflow through source fixes and PR checks. After opening the PR, call `bypass_remediation` with `action: open`, source review run ID, PR URL, branch, and the confirmed live audit run ID. Report the saved pending-merge state. Do not claim deployment or retest is complete at PR creation. After the user merges, call `bypass_remediation` with `action: replay` and the full merge SHA. A later `/bypass:start` resumes the saved checkpoint.
